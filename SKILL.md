# /master — мастеринг Suno-треков

Аргументы пользователя: $ARGUMENTS

Инструмент: `${CLAUDE_SKILL_DIR}/scripts/run.sh` (обёртка над `master.py` в своём venv).
Если он пишет «Окружение не установлено» — запусти `bash ${CLAUDE_SKILL_DIR}/scripts/setup.sh`
(с разделением на стемы: `--with-separator`, ~1 ГБ) и продолжи.

## Важно помнить

- **Ты не слышишь звук.** Решения принимаешь по замерам (report.md, spectrum.png), но финальное слово — за ушами пользователя. Всегда предлагай послушать `ab.html`.
- **Мастеринг не убирает «AI-следы» полностью** и не обманывает детекторы. Он ослабляет слышимые артефакты (резкие верха, шипящие, «блеск» тарелок) и выравнивает громкость. Не обещай большего.
- Оригиналы не изменяются: каждый запуск пишет новую папку `<трек>_master/vNN/`. Так можно сравнивать итерации.
- Исходник должен быть WAV/FLAC. Если дали MP3 — предупреди, что лучше скачать WAV из Suno, но можно продолжить.

## Порядок работы

1. **Найди вход.** Это файл (WAV/FLAC) или папка со стемами. Если пользователь не указал — спроси.
   Для папки стемов: проверь, что в ней нет полного микса рядом со стемами (иначе он сложится дважды). Лишнее исключай флагом `--exclude "mix|full"`.

2. **Анализ:** `run.sh analyze <вход> [--ref референс.wav]` — JSON с замерами.
   Коротко расскажи пользователю главное: громкость (LUFS), True Peak, признаки MP3/клиппинга, всплески резкости, разницу с референсом. Для стемов — проверь колонку `group` (vocals/drums/bass/other): если стем классифицирован неверно — переименуй копию или скажи об этом.

3. **Мастеринг:** `run.sh run <вход> [опции]`. Стартовые настройки:
   - стемы Suno → просто `run.sh run папка/`
   - полный WAV → `run.sh run трек.wav`
   - есть хороший референс того же жанра → добавь `--ref референс.wav` (при сильной перекраске `--ref-mix 0.5`)
   - много резкости/«металла» по анализу → `--preset strong`

   Разделение полного WAV на стемы (`--split vocals` или `--split 4`) на CPU занимает от нескольких минут до получаса на трек. **Спроси пользователя перед запуском** и предупреди о времени. `vocals` (вокал + инструментал) — быстрее и чаще всего достаточно.

4. **Проверка результата.** Прочитай `vNN/report.md` и посмотри `vNN/spectrum.png` (Read). Проверь:
   - LUFS попали в цели (±0.2), True Peak ≤ потолка;
   - лимитер не давит больше ~6 dB (в отчёте будет предупреждение);
   - «всплески резкости» снизились;
   - нет провалов/горбов в спектре, которых не было в оригинале.

5. **Покажи пользователю**: 3–5 строк — что сделано, главные цифры до/после, где файлы. Открой A/B: `xdg-open <папка>/vNN/ab.html`. Попроси послушать сравнение «A · Оригинал / B · Мастер» (они выровнены по громкости — это честное сравнение) и сказать, что не так.

6. **Итерации по отзыву** — запусти снова с поправками (будет следующая версия vNN):

   | Пользователь говорит | Что менять |
   |---|---|
   | режет уши, резко, «металл», шипит | `--preset strong`, или `--deharsh 6` (микс) / `--deess 9` (вокал), или `--air -1.5` |
   | глухо, тускло, нет воздуха | `--air 1.5`, `--preset light` |
   | мутно, «каша» в низах | `--mud -2.5` |
   | мало баса / низа | `--low 1.5` |
   | бас гудит, слишком много низа | `--low -1.5` |
   | вокал тонет | `--vocal-gain 1.5` (стемы/split) или `--presence 1` |
   | вокал слишком громкий | `--vocal-gain -1.5` |
   | плоско, нет удара, «пережато» | `--glue 0.5`, цель тише (`--targets -14,-12`), `--release 250` |
   | тихо по сравнению с другими треками | цели громче (`--targets -14,-10`); следи за GR лимитера |
   | узко / слишком широко | `--width 1.15` / `--width 0.9` |
   | искажения в MP3 | `--ceiling -1.5` |
   | звучит не как референс | `--ref-mix 1.0`; слишком сильно — `--ref-mix 0.4` |

   Меняй 1–2 параметра за раз и называй, что поменял. Значения dB — небольшие (±1…3).

7. **Сохранение звучания.** Когда пользователь доволен — предложи сохранить настройки как пресет:
   `run.sh run <вход> <те же флаги> --save-preset имя`. Дальше для новых треков: `run.sh run трек.wav --use имя`. Пресеты лежат в `${CLAUDE_SKILL_DIR}/presets/`.

## Что получается в папке vNN

- `master_-14LUFS.wav` — для стримингов (Spotify/YouTube/Apple нормализуют к ~−14).
- `master_-11LUFS.wav` и `.mp3` (320 kbps) — громче, для Telegram и соцсетей без нормализации.
- `premaster.wav` — после чистки и шины, до лимитера (если пользователь захочет домастерить в DAW).
- `ab.html` + `ab/` — A/B-сравнение, `spectrum.png` — спектр до/после/референс.
- `report.md` / `report.json` — замеры и все использованные настройки (воспроизводимо).

## Что делает цепочка

Стемы → для каждого своя чистка (вокал: де-эссер, подавление резкости и артефактов выше 10 кГц, компрессия; барабаны: подавление «блеска» 7–12 кГц; бас: обрезка верхов, моно; инструменты: −«грязь» 300 Гц, подавление блеска) → громкость стемов возвращается к исходному балансу Suno → сумма.
Полный микс → HPF 25 Гц, −«грязь», динамическое подавление 5.5–10 кГц и 11–16 кГц.
Дальше общее: (Matchering по референсу) → тон-EQ → «склеивающий» компрессор → лёгкая сатурация → моно-низ ниже 120 Гц → лимитер с упреждением по межсэмпловым пикам до целевых LUFS и потолка −1 dBTP. Динамическое подавление срабатывает только в моменты, когда полоса заметно громче обычного для трека, поэтому не «тушит» верха целиком.
